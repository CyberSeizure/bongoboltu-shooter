**Introduction**

Good morning/afternoon. Today I'll be presenting our 2nd semester project — a Space Shooter game built using Python and the Pygame library.

The game is a top-down arcade shooter. You control a spaceship, and waves of enemy ships come flying down toward you. Your job is to shoot them down before they pass you or crash into you. You have 5 lives, and each wave that clears spawns the next one — with more enemies each time. The game ends when you run out of lives or your health hits zero.

---

**Overall structure**

The code is organized using object-oriented programming. There are four main classes: `Laser`, `Ship`, `Player`, and `Enemy`.

We also have two functions — `main()` which runs the actual game, and `main_menu()` which shows the start screen.

---

**The Laser class**

The simplest class is `Laser`. Every time a ship fires, a new `Laser` object is created with a position and an image. It has three key methods — `move()` to travel across the screen, `off_screen()` to check if it has left the screen boundaries, and `collision()` to check if it has hit something. The collision uses a pygame feature called a mask, which does pixel-perfect detection instead of just checking rectangle overlap.

---

**The Ship class**

`Ship` is the parent class shared by both the player and the enemies. It holds the common properties every ship needs — position, health, a list of active lasers, and a cooldown timer. The cooldown prevents a ship from firing every single frame by locking the trigger for 30 frames after each shot.

By putting all of this shared logic in one place, we avoid rewriting the same code twice.

---

**The Player class**

`Player` extends `Ship`. It uses the blue laser and the player spaceship image. It overrides the `move_lasers()` method so that the player's lasers check for hits against the list of enemy ships — removing both the laser and the enemy on contact. It also draws a health bar below the ship, showing current health as a green bar over a red background.

---

**The Enemy class**

`Enemy` also extends `Ship`. There are three different enemy sprites, but they all use the same class — the image is just passed in as a parameter. Enemies move downward every frame using the `move()` method. They fire automatically using a random check — every frame there's a small random chance they shoot, which makes their behavior feel unpredictable.

---

**Collision detection**

Outside the classes, there is a standalone `collide()` function. It calculates the offset between two objects and uses `pygame.mask.overlap()` to check if their non-transparent pixels touch. This is used both for laser hits and for when an enemy ship physically crashes into the player.

---

**The game loop**

The heart of the whole program is the `main()` function and its `while` loop. This loop runs continuously — about 100 times per second. On every iteration it redraws the screen, reads keyboard input to move the player, moves all enemies and their lasers, checks for collisions, and updates lives and health accordingly.

When the enemies list becomes empty, the level counter goes up, the wave size increases by 5, and a fresh set of enemies spawns just above the visible screen and flies down into view.

If the player loses all lives or health, a game-over message appears and the loop exits after 3 seconds.

---

**Closing**

To summarize — this project taught us how to apply object-oriented principles like inheritance and method overriding in a real, working program. The `Ship` → `Player`/`Enemy` hierarchy kept the code clean and manageable. Overall it was a great way to see how concepts we learned in class come together to build something interactive.
